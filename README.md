# mica-bff

The spec for the Mica backend for frontend (BFF): the blocks the server sends and the clients render, and the generators that turn the spec into server code (`mica`) and client code (`next-ios`).

Two Mix projects ([ADR 0002](docs/adr/0002-dsl-and-spec.md)):

- `dsl/`: the generic part, app `:mica_bff_dsl`. The schema DSL (`defblock`, `field`), the Elixir and Swift generators and their mix tasks. It knows nothing about Mica's blocks. See [dsl/README.md](dsl/README.md) and [ADR 0001: spec format](dsl/docs/adr/0001-spec-format.md).
- `spec/`: Mica's block catalogue, app `:mica_bff_spec`.
  - `lib/mica_bff/blocks.ex`: the blocks (`MicaBff.Blocks`)
  - `config/config.exs`: the catalogue and namespaces the generators use
  - `fixtures/`: example payloads; generated code must encode and decode them exactly
  - `test/golden/`: the generated code as reviewed; the tests fail when the output changes

Blocks travel as JSON: `{"type": "section", "props": {"title": "...", "body": "...", "to": "/..."}}`.

```sh
cd spec
mix test   # the Swift tests need swiftc; without it they are skipped locally, never in CI
mix run -e 'IO.inspect(MicaBff.Blocks.__schema__())'

# one module per block (struct + to_map/1), e.g. Systems.BFF.Blocks.Section
mix bff.gen.elixir --out ../../mono/core/mica/systems/bff/blocks

# one file, BFF.swift: enum BFF.Block (one case per block + .unknown) and a struct per block
mix bff.gen.swift --out ../../next-ios/Next/BFF

# the DSL on its own
cd ../dsl && mix test
```

`--spec MODULE` and `--namespace NAME` override `config/config.exs`. Generated files start with a "Generated by mica-bff" header. A rerun replaces them, and never overwrites a hand-written file. A change that changes the generated code also updates `spec/test/golden`: run both generators with `--out test/golden/elixir` and `--out test/golden/swift`.

Views are hand-written in the app: switch over `BFF.Block` without `default:`, so a new block is a build error until it has a view.
